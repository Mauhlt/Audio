## minimp3 (MP3 decoder)

- Source: minimp3 by lieff, https://github.com/lieff/minimp3 (as bundled in dr_mp3)
- Licence: CC0 1.0 Universal (public domain dedication)
- Used in: `src/Formats/mp3/decoder.zig`, `layer3.zig`, `layer12.zig`, `synth.zig`, `bits.zig`
  and `scalar.zig` are a Zig port of its decoder; `tables.zig` holds its lookup tables,
  extracted verbatim. The encoder's Huffman tables are derived from those decode tables at
  compile time.

## Test data

The repository ships no audio files. All test data is generated by Zig code at test time, in
memory or in `std.testing.tmpDir` (`.zig-cache/tmp`), and nothing generated is committed:

- `src/testdata.zig`: `signal` synthesises tones, a linear sweep and white noise from
  `std.Random.DefaultPrng` with a fixed seed; `packWav` packs RIFF / RF64 WAVE files field by
  field; `mp3Header`, `silentFrame`, `xingFrame`, `id3v2`, `apev2` and `id3v1` build MPEG audio
  frames (all-zero side info and main data, which decode to silence), Xing / Info frames with
  the LAME delay / padding fields, and tags. The `LAME3.100` string written into the hand-built
  LAME field is a format identifier, not LAME code or output.
- `src/root.zig` tests encode generated signals with this library's own WAV, QOA and MP3
  encoders, and build the QOA oracle file from `src/Formats/qoa/scalar.zig`.
- Standards followed (no code taken): ISO/IEC 11172-3 and 13818-3 (MPEG audio), ITU-T G.711
  (A-law / mu-law), Microsoft RIFF WAVE and EBU RF64, the Xing / LAME header layout, ID3v1,
  ID3v2.4 and APEv2.

### Removed test files

These files had no recorded origin or licence (in particular `Music*.mp3`, music encoded with
LAME, source recording unknown) and were deleted:

- `src/Data/Read/Music11k.mp3`, `Music128.mp3`, `Music22k.mp3`, `Music48k320.mp3`,
  `MusicMono64.mp3`, `MusicVbr.mp3`, and their dr_mp3 decodes `Music*.mp3.wav`
- `src/Data/Read/Tone.qoa` (written by the reference `qoa.h`) and its decode `Tone.qoa.wav`
- `src/Data/Read/Tone8.wav`, `Tone16.wav`, `Tone24.wav`, `Tone24Extensible.wav`, `Tone32.wav`,
  `ToneFloat32.wav`, `ToneFloat64.wav`, `ToneAlaw.wav`, `ToneAlaw.ref.wav`, `ToneMulaw.wav`,
  `ToneMulaw.ref.wav` (Python `wave` module or hand-packed; no recorded command or source)
- `src/Data/Write/Tone.qoa` (a test output that had been committed)

They are still in the repository's public git history. Only a history rewrite (and a force
push) would remove them from GitHub; whether to do that is the owner's decision.
